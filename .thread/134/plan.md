# Issue #134 契約: ファイルツリーのディレクトリをデフォルトで折りたたむ

## 目的

ディレクトリモードのファイルツリーを、保存された状態が無いときは折りたたんで表示する。表示中のファイルの位置は見失わせず、ユーザーが開いたディレクトリは次に開いたときも開いたままにする。

## 開閉状態のモデル

開閉状態は 2 つの集合で持ち、どちらかに入っているディレクトリを開く（`open` = `expanded` ∪ `revealed`）。

- `expanded`: ユーザーがトグルで開いたディレクトリ。localStorage に保存する
- `revealed`: 表示したファイルの祖先として自動で開いたディレクトリ。メモリ上だけに持つ

下の表の `open` 列は、`expanded` 列の変化と合わせて `revealed` がどう変わるかを画面上の結果として書いている。開いているディレクトリをトグルで閉じると、両方の集合から取り除く。

操作ごとの遷移:

| 操作 | `open` | `expanded` | 保存 |
| --- | --- | --- | --- |
| SSR・初回クライアントレンダリング | 表示中のファイルの祖先 | 空 | しない |
| マウント後の復元 | 保存済み `expanded` ∪ 表示中のファイルの祖先 | 保存済み `expanded` | TTL パージと `lastAccess` の更新を書き込む |
| 閉じているディレクトリをトグル | 追加 | そのディレクトリと祖先を追加 | する |
| 開いているディレクトリをトグル | 削除 | 削除 | する |
| ファイル移動が成功（サイドバーのリンク、本文中の `/view?path=` リンク、戻る/進む） | 遷移先の祖先を追加 | 変えない | しない |
| ファイル移動が失敗・中断（取得失敗、abort） | 変えない | 変えない | しない |
| SSE でツリーが更新される | 変えない（初めて現れるパスのディレクトリは折りたたみで現れる） | 変えない | しない |
| 検索中 | 全ディレクトリを開いて描く（`open` 自体は変えない）。トグルは無効 | 変えない | しない |

- 自動で開いた祖先は保存しない。リロード・再訪で開いたまま戻るのはユーザーが開いたディレクトリと、そのとき表示中のファイルの祖先だけ
- ディレクトリを開くとき、その祖先（開く操作ができた時点で画面上は開いている）も `expanded` に加える。自動で開いた `a` の下で `a/b` を開くと、再訪で `a` と `a/b` が開いて戻る
- ディレクトリを閉じても子孫の `expanded` は残す。`a` を閉じて開き直すと、以前開いていた `a/b` も開いた状態で現れる
- ユーザーは自動で開いた祖先を折りたためる。その後に同じディレクトリ内のファイルへ移動すると、移動のたびに祖先を開くため再び開く
- ツリーから消えたディレクトリのパスは `open` / `expanded` から取り除かない。同じパスのディレクトリが現れると、消える前の開閉状態で現れる（ブランチの切り替えで消えて戻るディレクトリの開閉を保つ）
- 保存形式は `localStorage["file-tree-state"] = { [projectId]: { expanded: string[], lastAccess: number } }`
  - `expanded` 配列を持たないエントリ（旧 `collapsed` 形式を含む）は不正として読み捨てる。移行はしない。読み捨てたエントリは次の書き込みで消える
  - `lastAccess` はマウント後の復元とトグルで更新する（閲覧だけの再訪でも TTL が延びる）
  - TTL（`TTL_DAYS` = 30 日）によるパージとプロジェクト識別子による名前空間化は維持する
- 祖先を開く操作は `useFileTreeState(projectId, currentPath)` が `currentPath` の変化で行う。`currentPath` は移動が成功したときだけ変わる
- 祖先は `/` と `\` の両方で区切って求める。`FileTreeNode.path` は `path.relative` から作られ、Windows では `\` 区切りになる
- `Sidebar`・`FileTree`・`FileTreeItems`・`DirectoryItem` の `isOpen` は必須にし、`isOpen` が無いときに全展開する既定値を無くす。SSR は表示中のファイルの祖先だけを開く `isOpen` を渡す。`onToggle` は任意のまま（SSR と検索中は渡さない）

## 受け入れ基準

| # | 条件 | 観測方法 |
| --- | --- | --- |
| AC1 | 保存状態が無い状態でディレクトリモードを開くと、表示中のファイルの祖先以外のディレクトリはすべて折りたたまれている（`/` で最初のファイルがルート直下なら全ディレクトリが折りたたまれている） | browser / 自動テスト（SSR マークアップ） |
| AC2 | `/view?path=a/b/c.md` を開くと `a` と `a/b` が展開され、それ以外のディレクトリは折りたたまれている。SSR のマークアップも同じ | browser / 自動テスト（SSR マークアップ） |
| AC3 | 別のディレクトリにあるファイルへ SPA 遷移すると、遷移先の祖先ディレクトリが展開される。経路は本文中のリンク・戻る/進む・検索中のサイドバーのリンク（検索をクリアした後に祖先が開いている） | browser |
| AC4 | 移動が失敗したとき（存在しないファイルへのリンク）は開閉状態が変わらない。表示中のファイルが変わらない再描画（SSE のツリー更新など）でも開閉状態は変わらない | browser / 自動テスト（フック） |
| AC5 | 自動で展開された祖先は保存されない。`a/b/c.md` から `x.md` へ移ってリロードすると `a`・`a/b` は折りたたまれている | browser |
| AC6 | 自動で展開された祖先はトグルで折りたためる。その後に同じディレクトリ内の別ファイルへ移動すると再び開く | browser |
| AC7 | `collapsed` 形式の保存データだけが残っている状態で開くと、AC1/AC2 と同じ表示になる | browser / 自動テスト（parseStore） |
| AC8 | ディレクトリを展開してリロードすると展開状態が復元される。別のファイルを開いた再訪でも復元される。自動で開いた祖先の下で子ディレクトリを開いた場合は、再訪で祖先と子の両方が開いている | browser / 自動テスト |
| AC9 | 展開していたディレクトリを折りたたんでリロードすると、（表示中のファイルの祖先でなければ）折りたたまれたまま | browser |
| AC10 | 検索中は全ディレクトリが展開され、検索中のクリックで保存状態が変わらない。検索をクリアすると検索前の開閉状態に戻る（検索中にファイルへ移動した場合は、それに加えて遷移先の祖先が開いている） | browser |
| AC11 | `file-tree-state.test.ts` が新しい保存形式で通る。TTL パージと他プロジェクトのエントリ保持が維持されている | 自動テスト |
| AC12 | 初回クライアントレンダリングが SSR の DOM と一致する（保存状態の有無によらずハイドレーション時点の開閉は祖先だけ）。保存状態の反映はマウント後に行う。console にエラーが出ない | browser / 自動テスト（SSR マークアップ・フックの初回レンダー） |
| AC13 | SSE でツリーに初めて現れるパスのディレクトリが加わると、折りたたまれた状態で現れ、既存の開閉状態は変わらない | browser |
| AC14 | 閉じたディレクトリのシェブロンは右向き（›）、開いたディレクトリは下向き（∨）で、押すと開くことが画面から読める | browser |
| AC15 | Windows の区切り（`a\b\c.md`）でも祖先が開き、トグルで開いたディレクトリの祖先が保存される | 自動テスト |

## スコープ

- 対象: `src/client/lib/file-tree-state.ts`、`src/client/hooks/use-file-tree-state.ts`、`src/client/directory-app.tsx`、`src/components/navigation/*`、`src/server/routes/directory.tsx`、開閉状態の純関数（`src/core/file-tree-open-state.ts`）、各テスト
- 対象外: 旧 `collapsed` データの移行、`/` のときに選ばれる最初のファイルの選び方、パス表記の正規化（`./a` 等）、`.adr/0089.md` の書き換え（当時の判断記録として残す）、保存状態をサーバーへ渡して SSR に反映すること（保存状態がある再訪ではマウント後に開くディレクトリが増える。旧実装でもマウント後に閉じるディレクトリが出ており同じ性質）
