# ADR — Issue #134: ファイルツリーのディレクトリをデフォルトで折りたたむ

## ADR-001: 開閉状態を「ユーザーが開いた集合」と「自動で開いた集合」の 2 つで持つ

### Context

保存形式を `collapsed` から `expanded` に反転し、表示中のファイルの祖先を自動で開く。自動で開いた祖先の扱いには 2 案があった。

1. 単一の `expanded` 集合に祖先も加え、まとめて保存する
2. ユーザーがトグルで開いた `expanded`（保存する）と、自動で開いた `revealed`（メモリ上だけ）に分ける

案 1 は状態が 1 つで済むが、閲覧したファイルの祖先がすべて保存されるため、使うほど再訪時のツリーが開いていく。Issue の動機（初回表示で目的のファイルを探しにくい）に反し、Issue が復元対象とするのは「ユーザーが展開したディレクトリ」だけ。

### Decision

案 2 を採る。`src/core/file-tree-open-state.ts` の `FileTreeOpenState = { expanded, revealed }` とし、どちらかに入っていれば開く。

- トグルで開くと、そのディレクトリと祖先を `expanded` に加える。祖先を加えないと、自動で開いた `a` の下で開いた `a/b` が再訪で閉じた `a` の下に隠れる
- トグルで閉じると両方の集合から取り除く。子孫の `expanded` は残し、開き直すと元どおりに現れる
- 2 集合の和で開閉を決めるので、2 つの集合がどんな組み合わせでも正しい状態になる（`expanded ⊆ open` のような不変条件を保つ必要がない）
- 祖先を開くのはフック `useFileTreeState(projectId, currentPath)` の中で、`currentPath` が変わったとき。呼び出し側が遷移のたびに開く操作を呼ぶ形にすると、呼び忘れた経路で祖先が開かない
- 初期状態 `initialOpenState(currentPath)` を SSR（`renderDirectoryView`）とクライアントの初回レンダーの両方が使い、ハイドレーション時点の DOM を一致させる。そのため `isOpen` は `Sidebar` から `DirectoryItem` まで必須にし、未指定時の全展開フォールバックを無くした

### Consequences

- 良い点: 閲覧で保存状態が膨らまない。SSR と初回レンダーの規則が 1 関数に集約される
- トレードオフ: 保存状態がある再訪では、ハイドレーション後に保存済みのディレクトリが開く（SSR は保存状態を知らない）。旧実装でもハイドレーション後に保存済みのディレクトリが閉じており、同じ性質
- ツリーから消えたパスは集合から取り除かない。同じパスが戻ると消える前の開閉状態で現れる
