# 動作確認計画 — Issue #88: ファイル・ディレクトリの検索機能を追加する

**Issue:** #88
**作成日:** 2026-06-07

---

## 確認環境

このIssueの変更（クライアント側の検索機能）を確認するために必要な手順のみ記載。

> 注意: 検索機能はクライアント側コード（`src/client/`, `src/components/`, `src/core/`）の変更で、クライアントバンドル `src/server/renderer/client-bundle.js` は `scripts/build-client.mjs` による生成ファイル。`pnpm dev:server` はこのバンドルを再生成しないため、クライアントコードを変更したら**必ずバンドルを再ビルド**してからサーバーを起動する。新しい Tailwind ユーティリティクラスを追加した場合は CSS も再生成が必要。

### 検証環境の起動

```bash
# 1. CSS とクライアントバンドルを再生成（クライアント変更を反映）
pnpm build:css
pnpm build:client

# 2. ディレクトリブラウジングモードでサーバー起動（任意の複数ファイルを含むディレクトリを指定）
pnpm dev:server docs/ --port 3000 --no-open
```

ブラウザで `http://localhost:3000` を開いて確認する。

### デプロイ方法

なし（検証環境のみで確認できる）。

## 確認項目

### 1. 検索ボックスの表示

- **目的:** ディレクトリブラウジングモードのサイドバーに検索ボックスが表示されることを確認する
- **手順:**
  1. `pnpm dev:server docs/ --port 3000 --no-open` でサーバーを起動
  2. ブラウザで `http://localhost:3000` を開く
  3. サイドバー上部（タイトルの下、ファイルツリーの上）を見る
- **期待結果:** 検索ボックス（input）が表示されている。長いツリーをスクロールしても検索ボックスは固定で消えない
- **確認ポイント:** 検索ボックスがスクロール領域の外（固定位置）にあること

### 2. キーワードによるフィルタリング

- **目的:** 入力したキーワードに部分一致するファイル・ディレクトリのみが表示されることを確認する
- **手順:**
  1. 検索ボックスにファイル名の一部（例: `read`）を入力する
  2. ツリーの表示が絞り込まれるのを確認する
  3. 大文字（例: `READ`）でも同じ結果になることを確認する
- **期待結果:** キーワードに部分一致するファイル・ディレクトリのみが表示される。大文字小文字は区別されない
- **確認ポイント:** マッチしないファイル・ディレクトリが非表示になっていること

### 3. マッチしたノードの親パス保持

- **目的:** 深い階層のファイルがマッチした場合、その親ディレクトリも表示されパスが分かることを確認する
- **手順:**
  1. サブディレクトリ内のファイル名でしか一致しないキーワードを入力する
  2. マッチしたファイルとその親ディレクトリの表示を確認する
- **期待結果:** マッチしたファイルと、そこに至る親ディレクトリがすべて展開された状態で表示される（折りたたまれていても展開される）
- **確認ポイント:** 親ディレクトリが全展開され、マッチへのパスがたどれること

### 4. 「該当なし」表示

- **目的:** マッチが1件もない場合に「該当なし」が表示されることを確認する
- **手順:**
  1. 存在しない文字列（例: `zzzzzzz`）を検索ボックスに入力する
- **期待結果:** 「該当なし」を示すメッセージが表示される（ツリーは空）
- **確認ポイント:** 空白ではなく明示的に「該当なし」と分かる表示が出ること

### 5. `/` キーによるフォーカスショートカット

- **目的:** `/` キーで検索ボックスにフォーカスできることを確認する
- **手順:**
  1. ページ上の何もない場所をクリックしてフォーカスを外す
  2. `/` キーを押す
  3. 検索ボックスにフォーカスが移ることを確認する
  4. サイドバーが閉じている状態（モバイル幅）でも `/` で開いてフォーカスされることを確認する
- **期待結果:** `/` キー押下で検索ボックスにフォーカスが移る。`/` 文字自体は入力されない
- **確認ポイント:** サイドバーが閉じている場合は開いてからフォーカスされること

### 6. 検索クリアで元に戻る

- **目的:** 検索文字列をクリアすると元のツリー表示・折りたたみ状態に戻ることを確認する
- **手順:**
  1. いくつかのディレクトリを折りたたんだ状態にする
  2. 検索ボックスにキーワードを入力してフィルタする（全展開される）
  3. 検索ボックスを空にする
- **期待結果:** 検索前に折りたたんでいたディレクトリの状態が復元される
- **確認ポイント:** 検索中の全展開が折りたたみ state を破壊していないこと

## エッジケース・異常系

### 1. 入力要素フォーカス中の `/` キー

- **目的:** 検索ボックス等に入力中の `/` がショートカットに奪われないことを確認する
- **手順:**
  1. 検索ボックスにフォーカスした状態で `/` を入力する
- **期待結果:** `/` がそのまま文字として入力される（ショートカットは発火しない）

### 2. 検索中の SSE 更新

- **目的:** 検索アクティブ中にファイルが変更・削除されてもツリー表示が壊れないことを確認する
- **手順:**
  1. キーワードでフィルタした状態にする
  2. マッチしているファイルをエディタで編集・保存、またはマッチするファイルを削除する
- **期待結果:** SSE でツリーが更新され、再フィルタされる。マッチが0件になれば「該当なし」に遷移する。表示が壊れない

## 既存機能への影響確認

- **ファイルツリーのナビゲーション:** 検索していない通常状態で、従来通りファイルクリックでプレビュー表示・ディレクトリ折りたたみが動作するか
- **折りたたみ状態の永続化:** 通常状態での折りたたみが localStorage に保存され、リロード後も維持されるか
- **SSR/ハイドレーション:** 初回ロード時にコンソールにハイドレーションの不一致エラーが出ていないか（検索ボックスが SSR でも描画され、初回は空クエリ・全件表示）
