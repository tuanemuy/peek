# 動作確認計画 — Issue #89: ファイルツリーの折りたたみ状態を永続化する

**Issue:** #89
**作成日:** 2026-06-07

---

## 確認環境

このIssueの変更はクライアントのハイドレーション（`src/client/`）とサーバーの SSR（`src/server/`）の双方に及ぶ。クライアント側コードはビルド成果物 `src/server/renderer/client-bundle.js` に固められて `document.tsx` に埋め込まれるため、**クライアント変更を検証するには事前にクライアントバンドルの再ビルドが必須**（`dev:server` 単体ではソース変更が反映されない）。

### 検証環境の起動

CSS とクライアントバンドルをビルドしてからサーバーを起動する。

```bash
pnpm build:css
pnpm build:client
pnpm build:favicon
node dist/index.js <確認用ディレクトリ>   # フルビルド後に確認する場合
```

または開発時のループ（クライアント変更のたびに `pnpm build:client` を再実行）:

```bash
pnpm build:client        # クライアント変更を反映（変更のたびに実行）
pnpm dev:server <確認用ディレクトリ>   # 例: pnpm dev:server docs/
```

サーバーはデフォルト `http://localhost:3000`。別ポートで衝突確認する場合は `--port` を付ける。

### デプロイ方法

なし（ローカル CLI ツール。検証環境のみで確認できる）。

## 確認項目

### 1. 開閉状態がリロードで復元される

- **目的:** ディレクトリの開閉状態が localStorage に永続化され、リロード後も復元されること。
- **手順:**
  1. `pnpm dev:server docs/`（サブディレクトリを含むディレクトリを指定）でサーバー起動。
  2. ブラウザで `http://localhost:3000` を開く。
  3. ファイルツリー上の任意のディレクトリを 1 つ以上折りたたむ。
  4. ページをリロード（F5）する。
- **期待結果:** 折りたたんだディレクトリが折りたたまれたまま復元される。展開していたディレクトリは展開のまま。
- **確認ポイント:** DevTools の Application → Local Storage → `http://localhost:3000` に `file-tree-state` キーが作られ、`{ "<projectId>": { "collapsed": [...], "lastAccess": <number> } }` の形になっていること。なお初回訪問時点（まだ何も折りたたんでいない状態）でも、TTL 管理のため `collapsed: []` の空エントリ＋`lastAccess` が現プロジェクトに作られるのは正常挙動。

### 2. プロジェクト間で状態が衝突しない（origin 名前空間化）

- **目的:** 同一ポートで別ディレクトリを起動しても開閉状態が混ざらないこと。
- **手順:**
  1. ディレクトリ A で起動し、あるディレクトリを折りたたむ。
  2. サーバーを停止し、別のディレクトリ B（A とは別構成）で同じポートで起動する。
  3. 同じブラウザで `http://localhost:3000` を再訪する。
  4. B で適当に開閉し、再度 A で起動して A を再訪する。
- **期待結果:** B の初期表示は A の折りたたみ状態の影響を受けず全展開。A 再訪時は A で設定した折りたたみ状態が保たれている（`file-tree-state` 内で projectId ごとにエントリが分かれている）。
- **確認ポイント:** Local Storage の `file-tree-state` に projectId が 2 つ分存在すること。

### 3. デフォルト挙動（記録の無いノードは展開）

- **目的:** 永続状態に無いディレクトリが展開で表示されること。
- **手順:**
  1. 一部のディレクトリだけ折りたたんだ状態でリロードする。
  2. 起動中のディレクトリに新しいサブディレクトリ＋Markdown ファイルを追加する（SSE でツリー更新が走る）。
- **期待結果:** 既存の折りたたみ状態は維持され、新規追加ディレクトリは展開状態で出現する。

### 4. SSE ツリー更新時に開閉状態が壊れない

- **目的:** ファイル監視によるツリー差し替え後も既存の開閉状態が保持されること。
- **手順:**
  1. いくつかのディレクトリを折りたたむ。
  2. 起動中のディレクトリ配下でファイルを追加/削除/リネームし、ツリー更新（`tree-changed`）を発生させる。
- **期待結果:** 既存の折りたたみ状態は維持されたままツリーが更新される（開閉がリセットされない）。

### 5. SSR 初期描画の整合（ちらつき/警告無し）

- **目的:** SSR とハイドレーションの初期 DOM が一致し、ハイドレーション不一致警告やちらつきが出ないこと。
- **手順:**
  1. DevTools の Console を開いた状態で、折りたたみ状態を保存済みのページをリロードする。
  2. 表示直後の挙動を観察する。
- **期待結果:**
  - Console に Preact のハイドレーション不一致警告が出ない。
  - 初期表示は全展開で描画され、その後（マウント直後）に保存済みの折りたたみが適用される。大きなレイアウトジャンプ/ちらつきが無い（`useLayoutEffect` でペイント前反映のため、視認できる点滅は最小）。

## エッジケース・異常系

### 1. localStorage が壊れている / 利用不可

- **目的:** 不正な JSON やプライベートモードでもクラッシュしないこと。
- **手順:**
  1. DevTools で `localStorage.setItem('file-tree-state','{invalid')` を実行してリロード。
  2. （別途）プライベートウィンドウで開く、または localStorage を無効化した状態で開閉操作する。
- **期待結果:** エラーで画面が壊れず、全展開のデフォルトで動作する。開閉操作自体は（永続化されなくても）UI 上は機能する。

### 2. TTL パージ

- **目的:** TTL（30 日）超過のプロジェクトエントリが初期化時に破棄されること。
- **手順:**
  1. 複数 projectId のエントリがある状態で、DevTools から 1 つのエントリの `lastAccess` を 30 日以上前の epoch ms に書き換える。
  2. ページをリロードする。
- **期待結果:** リロード後の `file-tree-state` から古いエントリが消え、現在のプロジェクトの `lastAccess` が現在時刻に更新されている。現在のプロジェクトの折りたたみ状態は維持される。

## 既存機能への影響確認

- **サイドバー開閉/リサイズ（`use-sidebar`）:** 本変更と独立。開閉トグル・幅リサイズ・localStorage 永続化が従来どおり動くこと。
- **テーマ切替（`theme`）:** 影響なし。切替・永続化が従来どおり動くこと。
- **ファイル単体ビュー（Markdown/HTML）:** `projectId` を持たないファイルモードで例外が出ず従来どおり表示されること。
- **ファイルナビゲーション（ツリーからファイル選択）:** 折りたたみ状態管理の持ち上げ後もファイルリンク遷移・アクティブ表示が従来どおり動くこと。
