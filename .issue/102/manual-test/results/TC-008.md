# TC-008: エッジケース 5（`--host 0.0.0.0` で LAN 経由の接続がある状態での Ctrl+C）

**結果**: PASS
**実行時間**: 約 1 分
**セッション**: verify-tc-008
**ポート**: 3016
**Node**: v22.22.1
**対象**: `dist/index.mjs`（再ビルドなし）／フィクスチャ: `scratchpad/fixture`（ディレクトリモード）
**LAN IP**: `192.168.10.117`（`ipconfig getifaddr en0`）

## 目的

Issue の再現条件が `--host 0.0.0.0` である以上、**ループバック以外の実ソケット**が残っている状態でも `closeAllConnections()` が効いて有界時間で終了することを確認する。

別デバイスは用意できないため、testing.md の確認ポイント記載の代替（同一機から LAN IP 経由でアクセス）を採用。**接続がループバックではなく LAN IP 経由の実ソケットであることを `lsof` で確認**した。

### `lsof` による「ループバックではない実ソケット」の確認（実測出力）

リスニングソケット（`0.0.0.0` バインドの確認）:

```
node 4012 hikaru 14u IPv4 0x4cf38c195d48a4b8 0t0 TCP *:3016 (LISTEN)
```

Ctrl+C 直前の ESTABLISHED（peek プロセス自身の fd を対象に列挙）:

```
node 4012 hikaru 15u IPv4 0x56e25906d9d2c43a 0t0 TCP 192.168.10.117:3016->192.168.10.117:61155 (ESTABLISHED)
node 4012 hikaru 16u IPv4 0xd98aa7684638e416 0t0 TCP 192.168.10.117:3016->192.168.10.117:61156 (ESTABLISHED)
node 4012 hikaru 17u IPv4 0x521005670b7671a8 0t0 TCP 192.168.10.117:3016->192.168.10.117:61171 (ESTABLISHED)
```

集計:

| 判定キー | 件数 |
|---|---|
| `127.0.0.1:3016` を含む ESTABLISHED（ループバック） | **0** |
| `192.168.10.117:3016` を含む ESTABLISHED（LAN IP 経由） | **3** |

3 本の内訳は、agent-browser のドキュメント接続 + クライアント側 SSE 接続（2 本）と、`curl -N /sse`（1 本）。**ローカルループバック経路は 1 本も使われておらず、実ネットワークインターフェース（en0）のアドレスを経由したソケットのみ**が残った状態で SIGINT を送出している。

## 観測サマリー

| 項目 | 値 |
|---|---|
| バインド | `0.0.0.0`（`TCP *:3016 (LISTEN)`） |
| SIGINT 時の ESTABLISHED（非ループバック）| **3 本**（うち SSE 2 本） |
| ループバック接続 | 0 本 |
| exit code | **0** |
| 所要時間 | **42ms**（期待の 5 秒以内を大幅に下回る） |
| タイムアウト警告（`did not close within`）| **0 回** |
| ハング | なし |
| クライアント側 | `readyState=complete`。無限ローディングにならず接続断を検知 |

LAN IP 経由の実ソケット 3 本が残った状態でも、所要時間は TC-006 のループバック条件（39〜41ms）と**有意差なし**。`closeAllConnections()` がループバック以外のソケットにも効いており、Issue の再現条件（`--host 0.0.0.0` × 複数クライアント）でシャットダウンが有界時間で完了することを確認した。

## 失敗詳細

なし。
