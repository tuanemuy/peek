## 検出した既存の不具合（この PR の回帰ではない）

**ファイル URL へのディープリンク直アクセス時にライブリロードが反映されない。**

- `http://localhost:PORT/a.md` に直接アクセスした状態でファイルを編集すると、SSE イベント自体は届くが本文が更新されず、コンソールに `[peek] Failed to fetch content: HTTP 400` が出る
- **`origin/main`（46cc093）のビルドでも全く同じく再現**するため、本 PR の変更（`/sse` の 503 早期拒否・`clients.add` の `!closed` ガード・`node:timers/promises` 化）とは無関係
- 通常導線（ツリーからファイルを開く、`location.pathname === "/view"`）では正常に反映される
- 疑わしい箇所: `src/client/hooks/use-sse-updates.ts`（`getCurrentPath` 未設定で file モード分岐に落ちる疑い）と `src/server/routes/api.tsx` の `resolveAndValidatePath()`
- → Phase 5 でスコープ外 Issue として起票する

## testing.md の記述の修正

TC-007 の実行中に、testing.md エッジケース 2 の期待結果が実測と食い違っていることが判明したため修正した（**テスト手順の問題**であって実装の不具合ではない）:

- パイプライン全体に SIGINT を送る（＝実 Ctrl+C 相当）と `tee` が先に死ぬため、**シャットダウンの出力は丸ごとログから消える**。これは POSIX パイプの意味論であって peek の欠陥ではない
- 「短い出力は欠落しない」ことを確認したい場合は、**`tee` を生かしたまま peek の PID にだけ SIGINT を送る**手順が必要
- 修正内容: 手順に条件を 1 つ追加し、期待結果を 2 条件で書き分けた
