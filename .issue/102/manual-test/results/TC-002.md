## SSE 接続の確認方法

testing.md の確認ポイントどおり、**HTML 本体はプレビュー用 iframe（`#content-frame` → `/api/raw`）に隔離されて描画されるが、SSE 接続はホスト側（トップレベル）ドキュメントのインラインスクリプトが張る**。トップレベル側で張られていることを、次の **4 系統**で確認した（全 3 試行で実施・記録）。

1. **ブラウザのネットワーク記録（`agent-browser network requests --filter sse`）** — 主たる証拠。
   全 3 試行で `GET http://localhost:3010/sse (EventSource) 200` が 1 件記録された。
   **リクエストの initiator 種別が `EventSource`** であり、これは `html-document.tsx` の
   `var es = new EventSource("/sse");`（Issue 本文が引用しているコード）が実際に走ったことを意味する。
2. **トップレベルドキュメントであることの確認（`agent-browser eval`）**
   `{"url":"http://localhost:3010/","top":true,"inlineSse":true}` を全 3 試行で取得。
   - `top: true` … `eval` が iframe ではなくトップレベル実行コンテキストで走っている
   - `inlineSse: true` … そのトップレベル文書の `<script>` に `new EventSource` を含むインラインスクリプトが載っている
   - 試行 1 では併せて `iframe: "/api/raw"` を確認し、**iframe が読み込むのは HTML 本体（`/api/raw`）だけで `/sse` ではない**ことを裏取りした。
3. **サーバー側 ESTABLISHED 接続数（`lsof -nP -iTCP:3010 -sTCP:ESTABLISHED`）**
   起動前ベースラインが **0**、ページを開いた直後が 6 エントリ（3 ペア: 文書 / `/api/raw` / `/sse`）、
   放置後の SIGINT 直前は **4 エントリ（2 ペア）= `node ↔ Google Chrome` 1 本 + `node ↔ curl` 1 本**で安定。
   Chrome 側の 1 本は試行 1 で **70 秒放置後も維持**されており、通常の HTTP アイドル接続では説明できない（＝ SSE ストリーム）。
4. **保証用の `curl -N` SSE クライアント併張**
   `curl -sN http://localhost:3010/sse` をバックグラウンドで張り、全 3 試行で `HTTP/1.1 200 OK`
   （`content-type: text/event-stream`）を確認。SIGINT 時点で**ブラウザ + curl の 2 本**の SSE が生きている状態にした。

`snapshot --max-output 8000` は全 3 試行で 3512 bytes を取得し、トップレベル文書に iframe が描画されていることを確認した。

> 補足（手法上の注意、判定には影響しない）: TC-001 と同様に `performance.getEntriesByType('resource')` には `/sse` が現れない（返るのは `/api/raw` と `/favicon.ico` のみ）。EventSource は Resource Timing に記録されないため、この方法は SSE 接続の判定に使えない。

### この観測の意味

Issue 本文が引用している **第 2 の SSE クライアント実装（`html-document.tsx` のインラインスクリプト）**が実際に `/sse` を張った状態でも、シャットダウンは 40ms 前後で完了し、`server.close()` の 2000ms 期限に一度も到達しなかった。TC-001（ディレクトリモード = `src/client/lib/sse.ts` 側、10 試行 38〜42ms・警告 0/10）と**所要時間・警告有無ともに同水準**であり、SSE クライアント実装の違いによる終了性の差は観測されなかった。

「真因が生きたままタイムアウトに救われている」側の兆候は本条件でも一切観測されていない。

本試行が埋めた条件は「macOS × 実ブラウザ SSE（HTML ファイルモード）× Node 22 × `kill -INT`」であり、`kill -INT` は testing.md の表のとおり `^C` エコーとプロセスグループ配送を再現しない点は TC-001 と同じ。
