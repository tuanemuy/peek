**結果**: PASS（peek 側に不具合なし。ただし testing.md の期待結果 1 の記述に実測との差異あり — 下記「testing.md との差異」参照）

**セッション**: verify-tc-007
**ポート**: 3015
**Node**: v22.22.1
**対象**: `dist/index.mjs`（再ビルドなし）／フィクスチャ: `scratchpad/fixture`（ディレクトリモード）

## 目的（ADR-007 の妥当性確認）

計画フェーズで stdio drain を入れる案があったが、実測で **uncaught EPIPE により exit code が 0 → 1 に変わる**ことが確認されたため不採用とした（ADR-007）。本テストはその判断が正しかったこと（**drain 無しで exit 0 のまま**、かつ**短い出力なら欠落しない**）を実機で確認する。

## 実行ログ

すべて SSE 接続 1 本（`curl -N /sse`）を張った状態で実施。

### A. testing.md 記載どおりの `| tee` パイプライン（プロセスグループへ SIGINT ＝ 実 Ctrl+C 相当）

`node dist/index.mjs <fixture> --host 0.0.0.0 --port 3015 --no-open 2>&1 | tee /tmp/peek-shutdown.log` を bash の job control（`set -m`）で独立プロセスグループに置き、`kill -INT -<PGID>` で**グループ全体に同時配送**（＝端末の Ctrl+C と同一の配送）。

| # | 操作 | 期待結果 | 実際の結果 | 判定 |
|---|------|---------|-----------|------|
| A-1 | グループ SIGINT | ハングせず終了 | elapsed=178ms、hung=**no**、`wait` の返り値=**130**（= `tee` が SIGINT で死んだ状態） | PASS |
| A-2 | 同上 | 同上 | elapsed=157ms、hung=**no**、`wait`=130 | PASS |
| A-3 | 同上 | 同上 | elapsed=53ms、hung=**no**、`wait`=130 | PASS |
| A-log | `/tmp/peek-shutdown.log` の内容 | `Shutting down...` / `Server stopped. Bye!` が残る | **3 試行とも 12 行（起動時バナーのみ）。`Shutting down` 0 件 / `Server stopped. Bye!` 0 件 / `Received SIGINT` 0 件** | 差異あり（下記） |

**`$?` の確認ポイント**: testing.md のとおり、パイプライン経由では `$?` は `tee` の終了状態になる。実測でも `wait` の返り値は **130（= 128+SIGINT、`tee` がシグナル終了）** であり、peek の exit code ではない。zsh では `PIPESTATUS` が使えず（zsh は `pipestatus`）、かつバックグラウンド・パイプラインでは `wait` 後の `PIPESTATUS` も先頭要素しか持たないため、**peek 自身の exit code はこの形態では取得できない**。そのため下記 B / C で別手段を用いた。

### B. peek 自身の exit code を取る（FIFO でパイプを再現し、reader は生存）

`mkfifo` で peek の stdout をパイプにし、`tee` を FIFO の reader として起動。peek の PID を直接握って `wait` することで **peek 自身の exit code** を取得。

| # | 操作 | 期待結果 | 実際の結果 | 判定 |
|---|------|---------|-----------|------|
| B-1 | reader 生存のまま peek に SIGINT | peek exit 0・ログに全出力 | **peek_exit=0**、elapsed=43ms、hung=no、`Shutting down` **1 件**、`Server stopped. Bye!` **1 件**、`Received SIGINT` **1 件**、EPIPE/Error **0 件** | PASS |
| B-2 | 同上（`tee` に先に SIGINT を送るが非対話シェルの非同期ジョブは SIGINT を無視するため reader は生存） | 同上 | **peek_exit=0**、elapsed=40ms、`Shutting down` 1 件、`Bye!` 1 件、EPIPE 0 件 | PASS |

ログ末尾（B-1 / B-2 とも同一）:

```
[peek] Received SIGINT, shutting down...
┌   Shutting down...
│
└  Server stopped. Bye!
```

→ **`process.exit(0)` 直前の短い出力は欠落しない**ことが確認できた（testing.md 期待結果 1 の根拠部分）。

### C. 真の EPIPE 条件（パイプの reader を殺してから SIGINT）— ADR-007 の本丸

FIFO の reader（`tee`）を `kill -9` で先に消し、peek の stdout を**確実に broken pipe** にしてから SIGINT を送出。drain を入れていたら uncaught EPIPE で exit 1 になるはずの条件。

| # | 操作 | 期待結果 | 実際の結果 | 判定 |
|---|------|---------|-----------|------|
| C-1 | reader 消滅後に SIGINT | peek が uncaught EPIPE で落ちない（exit 0 のまま） | **peek_exit=0**、elapsed=43ms、hung=no | PASS |
| C-2 | 同上 | 同上 | **peek_exit=0**、elapsed=42ms、hung=no | PASS |
| C-3 | 同上 | 同上 | **peek_exit=0**、elapsed=152ms、hung=no | PASS |

## 観測サマリー

| 項目 | 値 |
|---|---|
| peek 自身の exit code | **全試行 0**（B ×2、C ×3。broken pipe 条件でも 0） |
| uncaught EPIPE によるクラッシュ | **0 回**（ログに `EPIPE` / `Error:` の出力なし） |
| ハング（10 秒超）| **0 回** |
| 所要時間 | 40〜178ms（全て 5 秒以内） |
| reader 生存時のログ欠落 | **なし**（`Shutting down...` / `Server stopped. Bye!` とも記録） |
| reader（`tee`）が同時に SIGINT で死ぬ場合のログ | **シャットダウン出力が丸ごと欠落**（A-log） |
| パイプライン経由の `$?` | **130（`tee` の終了状態）** — testing.md の注記どおり peek の exit code ではない |

**ADR-007 の判断は妥当**と結論できる。

- drain **無し**の現行実装では、パイプの読み手が消えた状態（C）でも peek は **exit 0** を維持し、uncaught EPIPE で落ちない。
- drain を入れていれば `process.stdout` への明示的な flush/drain 待ちが broken pipe に当たり、ADR-007 が実測した「exit code 0 → 1」の劣化を招く。現行実装はその劣化を回避できている。
- かつ、読み手が生きている通常のパイプ／リダイレクトでは短い出力が欠落しない（B、および TC-006 の `> file` リダイレクト全試行）。**drain 無しでもログ観測性は確保されている**。

## testing.md との差異（要注記）

testing.md エッジケース 2 の期待結果 1 は「`Shutting down...` と `Server stopped. Bye!` がログに残っている」であり、手順 3 には「`Ctrl+C` を 1 回押す（`tee` にも SIGINT が届き先に死ぬ）」と書かれている。

**この 2 つは両立しない。** 実測（A、3/3 試行）では、プロセスグループへの SIGINT で `tee` が即座に死ぬため、その後に peek が書くシャットダウン出力は**読み手がいないパイプに書かれて失われる**。ログには起動時バナー 12 行しか残らない。

これは **peek 側の欠陥ではない**:

- 期待結果 1 の括弧書きの根拠は「短い出力は **`process.exit(0)` 直前でも欠落しない**」＝ peek 側の出力打ち切りの有無を問うもので、これは B で **PASS**（読み手が生きていれば全出力が残る）。
- 読み手が死んだ後の書き込みが届かないのは POSIX パイプの意味論であり、peek には回避手段がない（むしろ回避しようとした drain が ADR-007 で不採用になった案）。
- 期待結果 2「peek 自体が uncaught EPIPE で落ちない」は C で **PASS**。

**推奨**: testing.md 側の期待結果 1 を「読み手（`tee`）が生存している場合はログに残る。`tee` が同じ SIGINT で先に死ぬ場合、シャットダウン出力はパイプごと失われるが、これは peek の欠陥ではなく、peek は exit 0 を保つ」に修正する。ログを確実に残したい場合は `| tee` ではなく `> file 2>&1` を使えばよい（TC-006 の全試行で欠落ゼロを確認済み）。
